Privileged accounts

Privileged access is still access control. Appendix C adds independent review and MFA expectations for Tier 2 and Tier 3.

Not every-word — S17 first, then G3; deep-read Shall and App C; Should = implement whenever possible.

Reading order: S17, then the same-theme G3 section, then Appendix C if the system is Tier 2 or Tier 3.

ShallDEC-PRIV-01

Do I need a privileged account for this task?

Only if a lesser right cannot do the task. Privileged use is named, justified, and time-bounded where your process allows.

Relevance
Administrators and anyone who has collected standing admin rights.
Applicability
Roles: Elevated end user, System / LAN administrator, and IT security administrator / unit.Stages: Any stage.Tiers: Tier 1, Tier 2, Tier 3.
Prerequisites
You can describe the task without using the words “just in case”.
Implementation guidance
Prefer a separate privileged account from daily mail and browsing. Record the grant. Remove it when the task ends.
Source
S17 §11 G3 §11

Shall App CDEC-PRIV-02

Is MFA required for this privileged logon?

For Tier 2 and Tier 3, Appendix C expects MFA for interactive privileged logon where it is feasible. If it is not feasible, the reason needs to be explicit and owned, not assumed.

Relevance
Administrators of Tier 2 and Tier 3 systems.
Applicability
Roles: System / LAN administrator and IT security administrator / unit.Stages: Any stage.Tiers: Tier 2, Tier 3.
Prerequisites
The tier is confirmed. You know whether the logon is interactive.
Implementation guidance
Check G3 Appendix C before you quote the control in a design. Baseline credential rules in G3 §11 still apply at Tier 1.
Source
G3 Appendix C S17 §11 G3 §11

ShallDEC-PRIV-03

Who reviews privileged accounts, and how often?

On every tier, administrative privileges and data access rights, including temporary access, shall be reviewed regularly so unnecessary or excessive rights can be removed. G3’s example is at least once a year, preferably twice, and the frequency shall be defined and documented. A check of high-privilege account use should be done by an independent party. Tier 2 and Tier 3 also take an Appendix C independent check at least every six months, by someone other than the person whose use is under review.

Relevance
Security unit and system administrators on every tier.
Applicability
Roles: System / LAN administrator and IT security administrator / unit.Stages: 07 Operations.Tiers: Tier 1, Tier 2, Tier 3.
Prerequisites
You know which accounts hold administrative privileges or data access rights. Confirm the tier before you apply the six-month Appendix C check.
Implementation guidance
Define and document the review frequency, then remove rights that are unnecessary or excessive. For Tier 2 and Tier 3, keep the Appendix C independent check at least every six months. Record findings on the gap template when this is your job.
Source
S17 §11 G3 §11 G3 Appendix C

ShallDEC-PRIV-04

Can the team share one administrator password?

No. Shared administrator passwords hide who did what. Issue individual privileged accounts, or the approved equivalent your process uses that still identifies the person.

Relevance
Any team that keeps a password in a ticket or a safe.
Applicability
Roles: System / LAN administrator and IT security administrator / unit.Stages: Any stage.Tiers: Tier 1, Tier 2, Tier 3.
Prerequisites
You are about to grant admin rights.
Implementation guidance
Replace the shared secret with named accounts. Treat a long-lived shared password as a gap.
Source
S17 §11 G3 §11
