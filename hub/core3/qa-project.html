Can we add security requirements after the design is frozen, during user testing?

Security requirements belong at initiation and design, while the scope can still change. Finding them at testing means a gap, not a plan. Fix the requirement and the test before go-live if the item is a Shall.

The system might be Tier 2. Can we go live and classify it later?

No. The tier drives which Appendix C controls apply. Confirm it with the owner before you treat go-live as done. Do not stamp the tier yourself to unblock a date.

A critical patch will miss the usual window. Who needs to know?

Follow the local vulnerability process. For Tier 2 and Tier 3, Appendix C expects DITSO visibility when a fix slips. Confirm that row in G3 Appendix C rather than quoting a number from memory.
