    Compliance, assessment, and testing

    Compliance is how the B/D shows the controls work, including legal duties, security risk assessment, and technical review.

    Not every-word — S17 first, then G3; deep-read Shall and App C; Should = implement whenever possible.

    Reading order: S17, then the same-theme G3 section, then Appendix C if the system is Tier 2 or Tier 3.

    Legend
    Shall mandatory — must do Should best practice — implement whenever possible May desirable best practice App C extra controls for Tier 2 or Tier 3. Tier 3 includes every Tier 2 control. Checkbox = optional self-progress tick. Stored only in this browser.

    ShallDEC-COMPLY-01

    Do legal and personal-data duties sit in IT security?

    Yes. Identifying legal, regulatory, and contractual duties, including personal data, is part of compliance. IT security does not replace the personal-data regime. It has to work with it.

    Relevance
    Project owners and the security unit.
    Applicability
    Roles: Application developer, IT security administrator / unit, and Management support.Stages: 01 Project initiation, 02 Design, 05 Testing.Tiers: Tier 1, Tier 2, Tier 3.
    Prerequisites
    You know whether the system handles personal data or another regulated set.
    Implementation guidance
    Name the duties with the owner who already advises the B/D. Open S17 §20 and G3 §20. Do not invent a filing or a legal conclusion here.
    Source
    S17 §20 G3 §20

    ShallDEC-COMPLY-02

    When do assessment and testing show up?

    Security risk assessment, audit, and technical review are how you learn whether controls work. They belong before production and when the system changes in a major way, not only after an incident.

    Relevance
    Project and security staff.
    Applicability
    Roles: Application developer and IT security administrator / unit.Stages: 05 Testing, 06 Go-live, 08 Change.Tiers: Tier 1, Tier 2, Tier 3.
    Prerequisites
    There is a system and a change worth assessing. The tier changes how heavy the Appendix C package is.
    Implementation guidance
    Book the assessment through the local route. Use the testing stage pack. For Tier 2 or Tier 3, read the Appendix C compliance rows before you set the scope.
    Source
    S17 §20 G3 §20 S17 §16

    Shall App CDEC-COMPLY-03

    What extra assurance applies at Tier 2 and Tier 3?

    Appendix C adds vulnerability scanning and penetration testing expectations for Tier 2, including Internet-facing systems, and a heavier annual package for Tier 3. Tier 3 inherits the Tier 2 rows.

    Relevance
    Security unit scoping an assessment.
    Applicability
    Roles: IT security administrator / unit leads.Stages: 05 Testing, 08 Change.Tiers: Tier 2, Tier 3.
    Prerequisites
    The tier and whether the system is Internet-facing are known.
    Implementation guidance
    Read the compliance rows in G3 Appendix C before you quote a frequency in a paper. This card is a pointer, not the appendix.
    Source
    G3 Appendix C S17 §20 G3 §20
